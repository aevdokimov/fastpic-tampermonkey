# FastPic — сразу полное изображение (Tampermonkey)

Юзерскрипт убирает «квест» из трёх кликов: если открыть ссылку вида
`https://fastpic.org/view/…html` или `https://fastpic.org/fullview/…html`,
скрипт сам находит оригинал и открывает его вместо страницы хостинга.

```
было:  /view/…html  →  клик  →  /fullview/…html  →  клик  →  iN.fastpic.org/big/…jpg?md5=…
стало: /view/…html  →  iN.fastpic.org/big/…jpg?md5=…            (один автоматический переход)
```

## Установка

1. Установите расширение **Tampermonkey**.
2. Откройте панель Tampermonkey → **Create a new script…** («Создать новый скрипт»).
3. Удалите заготовку и вставьте целиком содержимое `fastpic-fullview.user.js`.
4. `Ctrl+S` (Cmd+S) — скрипт сохранён и активен.

Альтернатива: в панели Tampermonkey откройте **Utilities → Import from file** и
выберите `fastpic-fullview.user.js`. Ещё вариант — перетащить файл `.user.js`
в окно панели Tampermonkey.

## Как это работает

Проверено запросами к fastpic.org (см. `test/resolve.test.mjs` — он гоняет
настоящий код скрипта против живого сайта):

1. **`/fullview/…html` отдаётся напрямую** — без cookie, без Referer, без
   антибот-токена. Внутри страницы есть готовая подписанная ссылка:

   ```html
   <script>var loading_img = 'https://i129.fastpic.org/big/2026/1111/b0/…jpg?md5=…&expires=…';</script>
   ```

2. Скрипт строит адрес `/fullview/…` из текущего пути (заменой `/view/` →
   `/fullview/`) и запрашивает его фоновым `fetch` **на `document-start`**,
   ещё до того, как страница успела отрисоваться. Поэтому промежуточные
   страницы с рекламой не мелькают: на время поиска документ скрыт
   (`HIDE_WHILE_RESOLVING`).

3. Найденный URL проверяется и открывается через `location.replace()` —
   то есть картинка занимает место страницы fastpic, а кнопка «Назад» ведёт
   сразу на форум, минуя интерстишиал.

4. Если что-то пошло не так (изображение удалено, сеть недоступна, вёрстка
   изменилась) — скрипт молча снимает «завесу» и оставляет страницу как есть.

### Почему нельзя просто «собрать» URL из ссылки

Путь действительно предсказуем (`/view/129/2026/1111/<hash>.jpg.html` →
`https://i129.fastpic.org/big/2026/1111/<последние 2 символа hash>/<hash>.jpg`),
но CDN требует подпись `md5`. Без неё отдаётся **302 обратно на `/view/…`** —
получился бы бесконечный цикл. Подпись короткоживущая (`expires` ≈ +2 ч) и
генерируется сервером, поэтому её нужно каждый раз забирать со страницы
`/fullview/`. К счастью, подпись не привязана ни к User-Agent, ни к
`Sec-Fetch-*`, поэтому добытую фоновым запросом ссылку можно спокойно
открыть навигацией.

### Рекламные «двойники»

fastpic подмешивает в страницы левые ссылки вида
`https://i114.fastpic.org/big/…/f00dadd78abb215662617bd877f98ca3.jpeg`
(в CSS и в пикселях-счётчиках). Поэтому скрипт берёт **только** переменную
`loading_img`, а найденные в разметке `/big/`-ссылки дополнительно фильтрует
по имени файла и по дате из текущего URL. Параметр `&dl=1` («Скачать
оригинал») вырезается — иначе браузер скачивал бы файл вместо показа.

## Настройки

В начале скрипта, блок `CFG`:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `TIMEOUT_MS` | `12000` | сколько ждать ответ `/fullview/` |
| `HIDE_WHILE_RESOLVING` | `true` | скрывать страницу, пока ищется оригинал (без мигания рекламы) |
| `OPEN_IN_NEW_TAB` | `false` | `true` — открыть картинку в новой вкладке и оставить fastpic-страницу |
| `MAX_NAVIGATION_ATTEMPTS` | `2` | лимит переходов по ссылке антибот-заглушки |
| `DEBUG` | `false` | подробный лог `[fastpic-full]` в консоли |

## Что скрипт намеренно не трогает

- `…html?info=1` — кнопка «Показать сведения о файле»: это осознанное действие.
- Удалённые изображения («Изображение не найдено»): редиректить некуда.
- Ссылки на сам i-хост (`iN.fastpic.org`) — там уже картинка.

## Ограничения

- Скрипт завязан на разметку fastpic (`loading_img`, кнопки на `/big/`).
  Если сайт поменяет вёрстку, понадобится небольшой апдейт — частично его
  прикрывают фолбэки (DOM текущей страницы и переход по ссылке
  антибот-заглушки).
- Полностью убрать задержку нельзя: остаётся один фоновый запрос страницы
  `/fullview/` (~80 КБ). Убрать и его можно только перехватом кликов по
  thumbnail на самом форуме — это отдельная задача (и там мешает CORS).
- `expires` у подписи короткий, поэтому финальные URL не кэшируются —
  каждый переход парсится заново.

## Тесты

```bash
npm test        # node test/resolve.test.mjs — живой прогон против fastpic.org
npm run check   # node --check fastpic-fullview.user.js
```

Тест читает сам `fastpic-fullview.user.js`, вырезает блок метаданных,
запускает оставшийся код в песочнице `node:vm` с моками `location`,
`document`, `sessionStorage` и настоящим `fetch`, и проверяет:

1. `/view/129/2026/1111/<hash>.jpg.html` → `https://i129.fastpic.org/big/2026/1111/b0/<hash>.jpg?md5=…&expires=…`
   (плюс `HEAD`-проверка, что по этой ссылке реально отдаётся `image/*`);
2. `/view/123/2024/0828/_<hash>.png.html` → `https://i123.fastpic.org/big/2024/0828/14/_<hash>.png?…`;
3. удалённое изображение → редиректа нет;
4. `?info=1` → скрипт не делает ни одного запроса;
5. недоступная сеть → редиректа нет, страница остаётся.

> Примечание: fastpic отдаёт однобайтовую заглушку `-` на запросы, где в
> `User-Agent` есть `HeadlessChrome`. Поэтому при проверке в headless-браузере
> нужно подменить User-Agent на обычный Chrome, иначе сайт отдаст заглушку
> (скрипт в этом случае корректно сдаётся и показывает страницу как есть).
